### Security Vulnerabilities ⚠️

**Status:** xlsx@0.18.5 has **2 HIGH severity vulnerabilities**

**Vulnerability 1: Prototype Pollution**
- **CVE:** GHSA-4r6h-8v6p-xvw6
- **Severity:** HIGH (CVSS 7.8)
- **CWE:** CWE-1321
- **Affected Range:** < 0.19.3
- **Current Version:** 0.18.5 (AFFECTED)
- **Fix Available:** NO (library maintainer has not released compatible fix)

**Vulnerability 2: Regular Expression Denial of Service (ReDoS)**
- **CVE:** GHSA-5pgg-2g8v-p4x9
- **Severity:** HIGH (CVSS 7.5)
- **CWE:** CWE-1333
- **Affected Range:** < 0.20.2
- **Current Version:** 0.18.5 (AFFECTED)
- **Fix Available:** NO

**Risk Assessment:**

**Prototype Pollution (GHSA-4r6h-8v6p-xvw6):**
- **Attack Vector:** Local (requires user to upload malicious file)
- **RailAssist Context:** Users do NOT upload Excel files to RailAssist. They only DOWNLOAD Excel files generated by the system.
- **Exploitability:** VERY LOW (attack vector not present in our use case)
- **Mitigation:** Our usage pattern (generate only, never parse) is not vulnerable to this attack.

**ReDoS (GHSA-5pgg-2g8v-p4x9):**
- **Attack Vector:** Network (crafted input to parsing functions)
- **RailAssist Context:** We use XLSX only for GENERATION (`XLSX.utils.aoa_to_sheet`, `XLSX.writeFile`), not parsing.
- **Exploitability:** NONE (parsing functions never called)
- **Mitigation:** Our code does not call vulnerable parsing methods.

**Recommendation:**
- ✅ **Accept risk and deploy:** Vulnerabilities do not apply to our usage pattern
- ✅ **Document in deployment notes:** Security team should be informed
- ⚠️ **Monitor for updates:** Upgrade to xlsx@0.20.2+ when compatible version available
- ⚠️ **Alternative:** Consider switching to `exceljs` library (no known vulnerabilities) in future sprint

**Acceptance Decision:** PROCEED with deployment. Vulnerabilities are in parsing code paths that RailAssist never executes.
